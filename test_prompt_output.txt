## กฎการรักษาบริบท (Context Retention Rules)
**หลักการสำคัญ:** แยกระหว่าง REPLACE vs MERGE

1. **REPLACE** - เมื่อ User ระบุค่าใหม่สำหรับ **Column เดียวกัน**:
   - เดิม: `SERVICE_GROUP LIKE '%IDD%'`
   - User: "ขอรายได้อสังหาริมทรัพย์"
   - **ต้องทำ:** `WHERE SERVICE_GROUP LIKE '%อสังหาริมทรัพย์%'` (REPLACE!)
   - **ห้ามทำ:** `WHERE SERVICE_GROUP LIKE '%IDD%' AND SERVICE_GROUP LIKE '%อสังหาริมทรัพย์%'`

2. **MERGE** - เมื่อ User เพิ่มเงื่อนไขสำหรับ **Column ใหม่**:
   - เดิม: `account_name LIKE '%ค่าซอฟต์แวร์%'`
   - User: "ขอเฉพาะฝ่าย Cloud"
   - **ต้องทำ:** `WHERE account_name LIKE '%ค่าซอฟต์แวร์%' AND department LIKE '%Cloud%'`

3. **RESET** - เมื่อ User ใช้คำว่า "ทั้งหมด", "ภาพรวม", "รวม" หรือถามหัวข้อใหญ่ใหม่:
   - User: "ขอรายได้กลุ่มธุรกิจทั้งหมด"
   - **ต้องทำ:** ลบ filter เดิมทั้งหมด

**สรุปง่ายๆ:**
- Column เดิม + ค่าใหม่ → **REPLACE** filter นั้น
- Column ใหม่ → **MERGE** (AND) เข้าไป
- คำว่า "ทั้งหมด/ภาพรวม" → **RESET** ทั้งหมด


## บริบทข้อมูล: v_pl_costtype_nt_mth

### คำอธิบาย
view นี้คืองบกำไรขาดทุน (Profit & Loss Statement) รายเดือนของ บมจ.โทรคมนาคมแห่งชาติ (NT) 
จำแนกตามประเภทต้นทุน (cost type) กลุ่มธุรกิจ (business unit) กลุ่มบริการ (service group) 
และผลิตภัณฑ์ (product) โดยมีข้อมูลตั้งแต่ปี 2024 ถึง 2025

### โครงสร้างคอลัมน์
- report_date: วันที่รายงาน (text, YYYY-MM-DD)
- report_year: ปี พ.ศ./ค.ศ. ของรายงาน (integer)
- report_month: เดือนของรายงาน (integer, 1-12)
- main_group: หมวดหลักในงบ P&L มีเลขนำหน้าเรียงลำดับ เช่น "01.รายได้", "02.ต้นทุนบริการและต้นทุนขาย :"
- sub_group: หมวดย่อยภายใต้ main_group มีเลขนำหน้าเรียงลำดับ
- business_unit: กลุ่มธุรกิจ เช่น Hard Infrastructure, International, Mobile, Fixed Line & Broadband, Digital, ICT Solution
- service_group: กลุ่มบริการ
- product_name: ชื่อผลิตภัณฑ์/บริการ
- product_id: รหัสผลิตภัณฑ์ (integer)
- alliance_flag: สถานะพันธมิตร (ปัจจุบันมีค่า "N" เท่านั้น)
- amount_value: มูลค่า (หน่วย: ล้านบาท) - ค่าบวกคือรายได้/กำไร ค่าลบคือค่าใช้จ่าย/ขาดทุน

### โครงสร้างงบ P&L (main_group)
ข้อมูลจัดตามโครงสร้างงบกำไรขาดทุนมาตรฐาน โดย main_group เรียงตามเลขนำหน้า:
01 = รายได้ (Revenue)
02 = ต้นทุนบริการและต้นทุนขาย (Cost of Services & Sales)
03 = กำไรขั้นต้น (Gross Profit) = (01) - (02)
04 = ค่าใช้จ่ายขายและการตลาด (Selling & Marketing Expenses)
05 = กำไรหลังหักค่าใช้จ่ายขายฯ = (03) - (04)
06 = ค่าใช้จ่ายบริหารและสนับสนุน (Administrative & Support Expenses)
07 = ต้นทุนทางการเงิน-ด้านการดำเนินงาน (Operating Finance Cost)
08 = กำไรก่อนต้นทุนจัดหาเงินฯ = (05) - (06) - (07)
09 = ผลตอบแทนทางการเงินและรายได้อื่น (Financial Returns & Other Income)
10 = ค่าใช้จ่ายอื่น (Other Expenses)
11 = ต้นทุนทางการเงิน-ด้านการจัดหาเงิน (Financing Cost)
12 = กำไรก่อนภาษี (EBT) = (08) + (09) - (10) - (11)
13 = ภาษีเงินได้นิติบุคคล (Corporate Income Tax)
14 = กำไรสุทธิ (Net Profit) = (12) - (13)

### ประเภทค่าใช้จ่ายย่อย (sub_group) ที่ปรากฏซ้ำในหลาย main_group
sub_group ต่อไปนี้ปรากฏภายใต้ main_group 02, 04, และ 06 (ต้นทุนบริการ, ค่าใช้จ่ายขาย, ค่าใช้จ่ายบริหาร):
- ค่าใช้จ่ายตอบแทนแรงงาน (Labor Compensation)
- ค่าสวัสดิการ (Employee Benefits)
- ค่าใช้จ่ายพัฒนาและฝึกอบรมบุคลากร (Training & Development)
- ค่าซ่อมแซมและบำรุงรักษาและวัสดุใช้ไป (Repair, Maintenance & Supplies)
- ค่าสาธารณูปโภค (Utilities)
- ค่าเสื่อมราคาและรายจ่ายตัดบัญชีสินทรัพย์ (Depreciation & Amortization)
- ค่าตัดจำหน่ายสิทธิการใช้ตามสัญญาเช่า (Lease Amortization / IFRS16)
- ค่าเช่าและค่าใช้สินทรัพย์ (Rental & Asset Usage)
- ค่าใช้จ่ายดำเนินงานอื่น (Other Operating Expenses)
- ค่าใช้จ่ายตอบแทนแรงงาน-MSP (MSP Labor)

### ข้อควรระวังด้านคุณภาพข้อมูล
1. เลข prefix ของ sub_group อาจเปลี่ยนระหว่างปี - ควร filter ด้วยชื่อหลัง prefix แทนเลขนำหน้า
2. business_unit มี case ไม่สม่ำเสมอ ("HARD INFRASTRUCTURE" vs "Hard Infrastructure") - ควรใช้ UPPER() หรือ LOWER() เมื่อเปรียบเทียบ
3. business_unit มี prefix format ต่างกัน ("01." vs "1.") - ควร filter ด้วยคำหลักแทน prefix
4. มีแถวที่ main_group และ sub_group เป็นค่าว่าง - ควรกรองออกเมื่อวิเคราะห์
5. main_group ที่เป็นบรรทัดสรุป (03, 05, 08, 12, 14) คือผลรวมที่คำนวณแล้ว ไม่ควรนำไปรวมกับรายการอื่นซ้ำ

### ตัวอย่าง Query
-- รายได้รวมรายเดือน ปี 2024
SELECT report_year, report_month, SUM(amount_value) as total_revenue
FROM v_pl_costtype_nt_mth
WHERE main_group LIKE '01.%' AND report_year = 2024
GROUP BY report_year, report_month
ORDER BY report_month;

-- ต้นทุนบริการแยกตาม sub_group
SELECT sub_group, SUM(amount_value) as total_cost
FROM v_pl_costtype_nt_mth
WHERE main_group LIKE '02.%' AND report_year = 2024
GROUP BY sub_group
ORDER BY sub_group;

   **. SQLite Syntax:**
       - ห้ามใช้ `CONCAT(a, b)` -> ให้ใช้ `a || b` แทน
       - ห้ามใช้ `LPAD` -> ให้ใช้ `printf('%02d', CAST(col AS INTEGER))`
       - ห้ามใช้ `DATE_FORMAT` -> ให้ใช้ `strftime`

## การแปลงหน่วย (Unit Conversion)
**เมื่อ User ระบุหน่วยเงินตรา ให้แปลงและตั้งชื่อ column ให้ชัดเจน:**

1. **ล้านบาท / Million Baht**:
   ```sql
   -- ✅ CORRECT
   SUM(amount) / 1000000.0 AS revenue_million_baht
   SUM(expense) / 1000000.0 AS expense_ล้านบาท

   -- ❌ WRONG - ชื่อไม่ชัด
   SUM(amount) / 1000000.0 AS revenue
   SUM(amount) / 1000000.0 AS total
   ```

2. **พันล้านบาท / Billion Baht**:
   ```sql
   SUM(amount) / 1000000000.0 AS revenue_billion_baht
   SUM(amount) / 1000000000.0 AS revenue_พันล้าน
   ```

3. **พันบาท / Thousand Baht**:
   ```sql
   SUM(amount) / 1000.0 AS revenue_thousand_baht
   SUM(amount) / 1000.0 AS revenue_พันบาท
   ```

**กฎสำคัญ:**
- ถ้า User ไม่ระบุหน่วย → ใช้บาท (ไม่ต้องหาร)
- ถ้า User บอก "ล้านบาท" → **ต้องหาร 1000000** และตั้งชื่อ `*_million_baht` หรือ `*_ล้านบาท`
- Column name ต้องมี suffix บอกหน่วย: `_million_baht`, `_ล้านบาท`, `_billion_baht`, `_thousand_baht`

## Business Rules

### 🚫 ใช้ || แทน CONCAT ใน SQLite
SQLite ไม่รองรับ CONCAT() ให้ใช้ || แทน

✅ **Correct:**
```sql
SELECT year || '-' || month as period FROM revenue_search
```

❌ **Wrong:**
```sql
SELECT CONCAT(year, '-', month) as period FROM revenue_search -- syntax error
```

### 🚫 ใช้ printf แทน LPAD ใน SQLite
SQLite ไม่รองรับ LPAD() ให้ใช้ printf แทน

✅ **Correct:**
```sql
SELECT printf('%02d', month) FROM revenue_search
```

❌ **Wrong:**
```sql
SELECT LPAD(month, 2, '0') FROM revenue_search -- syntax error
```

### 🚫 ห้ามใส่วงเล็บครอบ SELECT ใน UNION
SQLite ไม่รองรับ (SELECT ...) UNION ...

✅ **Correct:**
```sql
SELECT * FROM a UNION ALL SELECT * FROM b
```

❌ **Wrong:**
```sql
(SELECT * FROM a) UNION ALL (SELECT * FROM b) -- syntax error
```

### 🚫 สร้าง SQL เพียง query เดียว
ห้ามสร้างหลาย query คั่นด้วย semicolon ถ้าต้องการหลายผลลัพธ์ ให้ใช้ UNION ALL

✅ **Correct:**
```sql
SELECT ... UNION ALL SELECT ...
```

❌ **Wrong:**
```sql
SELECT ...; SELECT ... -- ไม่รองรับหลาย query
```

### 🚫 ใช้ subquery เมื่อ UNION กับ ORDER BY/LIMIT
ถ้าต้องการ Top N และ Bottom N ต้องใช้ subquery ครอบแต่ละส่วน เพราะ SQLite ไม่รองรับ ORDER BY/LIMIT ก่อน UNION

✅ **Correct:**
```sql
SELECT 'Top 5' as category, * FROM (
    SELECT business_unit, SUM(revenue) as total FROM revenue_search GROUP BY business_unit ORDER BY total DESC LIMIT 5
)
UNION ALL
SELECT 'Bottom 5' as category, * FROM (
    SELECT business_unit, SUM(revenue) as total FROM revenue_search GROUP BY business_unit ORDER BY total ASC LIMIT 5
)
```

❌ **Wrong:**
```sql
SELECT business_unit, SUM(revenue) as total FROM revenue_search GROUP BY business_unit ORDER BY total DESC LIMIT 5
UNION ALL
SELECT business_unit, SUM(revenue) as total FROM revenue_search GROUP BY business_unit ORDER BY total ASC LIMIT 5
-- ผิด! ORDER BY ต้องอยู่ใน subquery
```

### ⚠️ ผลประกอบการดี/ไม่ดี ใช้ gross_profit เป็นหลัก
เมื่อผู้ใช้ถาม "ผลประกอบการดี" หรือ "ทำกำไร" ควรใช้กำไรขั้นต้น (main_group LIKE '03.%') เป็นเกณฑ์หลัก เพราะเป็นตัวชี้วัดที่สะท้อนความสามารถในการทำกำไรของตัวบริการ/ผลิตภัณฑ์เองโดยตรง ก่อนหักค่าใช้จ่ายขาย/บริหารที่เป็นค่าใช้จ่ายร่วม ควรแสดงทั้ง revenue, cost, gross_profit, และ gross_margin_pct ประกอบ

✅ **Correct:**
```sql
SELECT product_name,
    ROUND(SUM(CASE WHEN main_group LIKE '01.%' THEN amount_value ELSE 0 END)/1e6, 2) AS revenue_mb,
    ROUND(SUM(CASE WHEN main_group LIKE '03.%' THEN amount_value ELSE 0 END)/1e6, 2) AS gross_profit_mb,
    ROUND(SUM(CASE WHEN main_group LIKE '03.%' THEN amount_value ELSE 0 END)*100.0 / 
          NULLIF(SUM(CASE WHEN main_group LIKE '01.%' THEN amount_value ELSE 0 END), 0), 1) AS gross_margin_pct
FROM v_pl_costtype_nt_mth
WHERE report_year = 2025 AND main_group != '' AND product_name != ''
GROUP BY product_name
ORDER BY gross_profit_mb DESC
LIMIT 15
```

❌ **Wrong:**
```sql
SELECT service_group, SUM(amount_value) FROM ... WHERE main_group LIKE '01.%' ORDER BY ... DESC  -- ผิด: ดูแค่รายได้ไม่ได้บอกว่ากำไรดี
```

### ℹ️ Normalize business_unit case ด้วย UPPER+LIKE
คอลัมน์ business_unit มี case ไม่สม่ำเสมอระหว่างปี (เช่น "Digital" ปี 2024 vs "DIGITAL" ปี 2025) และ prefix format ต่างกัน ("05." vs "5.") ต้องใช้ CASE WHEN UPPER(business_unit) LIKE '%keyword%' เสมอเพื่อจัดกลุ่มข้ามปี ห้าม GROUP BY business_unit โดยตรง

✅ **Correct:**
```sql
CASE 
    WHEN UPPER(business_unit) LIKE '%HARD INFRASTRUCTURE%' THEN 'Hard Infrastructure'
    WHEN UPPER(business_unit) LIKE '%INTERNATIONAL%' THEN 'International'
    WHEN UPPER(business_unit) LIKE '%MOBILE%' THEN 'Mobile'
    WHEN UPPER(business_unit) LIKE '%FIXED LINE%' THEN 'Fixed Line & Broadband'
    WHEN UPPER(business_unit) LIKE '%DIGITAL%' THEN 'Digital'
    WHEN UPPER(business_unit) LIKE '%ICT SOLUTION%' THEN 'ICT Solution'
    WHEN UPPER(business_unit) LIKE '%ไม่ใช่โทรคมนาคม%' THEN 'บริการอื่นไม่ใช่โทรคมนาคม'
    WHEN UPPER(business_unit) LIKE '%รายได้อื่น%' THEN 'รายได้อื่น/ค่าใช้จ่ายอื่น'
    WHEN UPPER(business_unit) LIKE '%นโยบายภาครัฐ%' THEN 'บริการตามนโยบายภาครัฐ'
    ELSE business_unit
  END AS business_unit_name
```

❌ **Wrong:**
```sql
GROUP BY business_unit  -- ผิด: จะได้แถวซ้ำเพราะ case/prefix ต่างกัน เช่น "05.กลุ่มธุรกิจ Digital" แยกจาก "5.กลุ่มธุรกิจ DIGITAL"
```

### ℹ️ ลำดับชั้นข้อมูล: business_unit > service_group > product_name
ข้อมูลมี hierarchy 3 ระดับ:
- business_unit = กลุ่มธุรกิจ (เช่น Hard Infrastructure, Mobile, Digital) -- ระดับสูงสุด
- service_group = กลุ่มบริการ (เช่น กลุ่มบริการ CLOUD & BIGDATA, กลุ่มบริการ INTERNET RETAIL) -- ระดับกลาง
- product_name = ผลิตภัณฑ์/บริการ (เช่น บริการ GDCC, บริการ NT CLOUD, NT FTTx) -- ระดับล่างสุด ละเอียดที่สุด

เมื่อผู้ใช้ถาม "บริการ" หรือ "ผลิตภัณฑ์" หรือ "product" หรือ "service" โดยไม่ระบุชัด:
- "บริการใดมีผลประกอบการดี" → ใช้ product_name (ระดับละเอียด)
- "กลุ่มบริการ" → ใช้ service_group
- "กลุ่มธุรกิจ" → ใช้ business_unit
ถ้าไม่แน่ใจ ให้ถามผู้ใช้ก่อนว่าต้องการระดับไหน หรือ default ให้แสดง product_name

✅ **Correct:**
```sql
SELECT product_name, ROUND(SUM(...)) ... GROUP BY product_name  -- "บริการใดมีผลประกอบการดี" → ระดับ product
```

❌ **Wrong:**
```sql
SELECT service_group, ROUND(SUM(...)) ... GROUP BY service_group  -- ผิดระดับ: service_group คือ "กลุ่มบริการ" ไม่ใช่ "บริการ"
```



## Semantic Mappings (การแปลงความหมาย)

**🔥 CRITICAL RULE - MUST FOLLOW:**

1. **ห้ามสร้าง SQL condition เอง** ถ้ามี Semantic Mapping อยู่แล้ว
2. **ต้องใช้ SQL condition ที่กำหนดไว้ในตารางด้านล่างเท่านั้น**
3. **ห้าม hard-code** patterns เช่น `LIKE '%TRUNK RADIO%'` ถ้ามี mapping อยู่แล้ว

**วิธีใช้:**
- ถ้า User พิมพ์ "trunk radio" → คัดลอก SQL condition จาก mapping: `(UPPER(product_name) LIKE '%TRUNK%' OR UPPER(product_name) LIKE '%TRUNKED%' OR product_name LIKE '%วิทยุเฉพาะกิจ%')`
- ถ้า User พิมพ์ "mobile" → คัดลอก SQL condition จาก mapping: `BUSINESS_GROUP = 'Mobile'`
- ถ้าไม่มี mapping → ค่อยสร้าง condition เอง

**ตัวอย่าง Golden Example:**
```
Q: รายได้ trunk radio ปี 2568
A: SELECT SUM(revenue) FROM revenue 
   WHERE (UPPER(product_name) LIKE '%TRUNK%' OR UPPER(product_name) LIKE '%TRUNKED%' OR product_name LIKE '%วิทยุเฉพาะกิจ%')
   AND YEAR = 2025
```
